## 2. Key Learnings

### Sigil Indexes Observed LLM Traffic, Not Live Chat
`sigil_query` with `search_conversations` filters on LLM generations captured by Grafana AI Observability. The current interactive session may not appear until indexing catches up (typically minutes to hours). Always pair `search_conversations` with `list_conversations` and artifact-API checks (skills, investigations, automations) for a complete picture.

### Multi-Source Reconstruction Is the Fallback Pattern
When Sigil shows no data, pivot to other Grafana Assistant APIs:
- `search_skills` → what templates or knowledge was created
- `investigation list` → what systematic analyses ran
- `manage_automations list` → what scheduled tasks are configured
- The live conversation itself is always a primary source

### Skills as Reusable Prompt Templates
Storing a complex multi-section prompt as a skill makes it version-controlled inside Grafana, discoverable via `search_skills`, and evolvable without re-entering the full prompt each session. This is the lightweight equivalent of a Jinja template in a traditional automation stack.

### GitHub MCP as a GitOps Sink
`push_files` commits structured artifacts (Markdown, JSON, YAML) from a single Assistant turn. No local git clone required. This enables:
- Every digest → a versioned commit
- Every runbook → a PR-reviewed document
- Every post-mortem → an immutable audit record

### Automation Context Restriction
`manage_automations` is blocked inside automation-triggered runs (by design — prevents self-modification loops). Any workflow that needs to inspect or modify automations must run from an interactive session.

### Naming and Date Convention
When writing files with date-based names, always use the user's **local** date (from context `time_iso_local`), not UTC — especially important for users in negative UTC offsets where the UTC date is already the next day.

## 3. How Enterprise Customers Use This at Scale

### Daily Digest as an Operational Ritual
Mature SRE and platform-engineering organizations run digest automations on a schedule (`0 8 * * 1-5` for 8am weekday handoffs). Enterprise digests aggregate across multiple signal types:
- Overnight alert state changes and resolution events (via `alerting_historian`)
- Investigations started or completed during the previous shift
- Cost and cardinality anomalies from CMAB usage alerts
- On-call handoff summaries pulled from IRM schedules
- Deployment events from CI/CD webhook integrations

At scale, separate digest templates exist per team domain (infra, application, security, cost), each committing to team-owned subdirectories in a shared observability monorepo.

### GitOps Documentation at Scale
Enterprise organizations extend the GitHub MCP commit pattern into a living observability knowledge base:
- **Runbooks**: Auto-drafted from investigation summaries, merged via PR after on-call engineer review
- **Post-mortems**: Generated from IRM incident timelines; PRs trigger Slack notifications to stakeholders
- **Architecture Decision Records (ADRs)**: Conversations that result in infrastructure changes produce `/docs/adr/NNNN-title.md` entries
- **Compliance audit trails**: Git history of digest commits provides timestamped, tamper-evident records for SOC 2 Type II, ISO 27001, and HIPAA operational reviews

### Tenant-Wide Skill Libraries
Enterprise accounts maintain `scope: "tenant"` skill libraries with 50–200 skills covering:
- Every critical service's runbook and escalation path
- Known failure patterns and their confirmed fixes
- Data dictionary entries for key metrics and dashboards
- Regulatory compliance checklists (e.g., HIPAA audit steps, PCI incident response)

Teams run quarterly skill reviews: stale skills are archived, new post-mortem learnings are promoted into skills, and the library is syndicated to onboarding documentation.

### Sigil for LLM Traffic Governance
Enterprises routing internal AI products (chatbots, copilots, AI-assisted workflows) through Grafana AI Observability use `search_conversations` to power:
- Daily error-rate dashboards segmented by model and service
- Evaluator rules that flag hallucinations, toxicity, or policy violations before they reach end users
- Cost attribution by team and service using per-generation token counts
- Guard rules that block sensitive data patterns (PII, credentials) in real time

### Multi-Team Automation Governance
At scale, `manage_automations` with `scope: "tenant"` creates shared scheduled tasks visible to all engineers. Teams establish:
- Naming conventions (`team-function-frequency`, e.g., `infra-digest-daily`)
- Ownership labels in automation descriptions
- A central automation registry (a Markdown file in the same repo) documenting each automation's purpose, owner, and cron schedule
