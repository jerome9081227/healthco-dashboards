## 2. Key Learnings

### Sigil Indexing Has Latency — Plan for It
The Sigil `search_conversations` API returned zero results for the 24-hour window even though a live conversation was in progress. The most recent indexed conversations were ~19 days old. This means:
- Digests generated immediately after a session will not capture that session in Sigil.
- **Mitigation:** Run the digest automation on a slight delay (e.g., 2–4 hours after end of day), or accept that today's session appears in tomorrow's digest.
- The current live conversation is always the most recent context — it just isn't indexed yet.

### Prompt Pattern: Structured Digest with Multi-Tool Orchestration
The prompt that worked: explicitly enumerate the four output sections, name the data source (Sigil), name the destination (GitHub repo + path), and specify the date format. This removes ambiguity from the assistant and produces a deterministic output. Reusable template:

```
Review my last 24h of Grafana Assistant conversations and generate a digest with sections:
[section list]. Commit to [owner/repo] under [path/YYYY-MM-DD.md] via GitHub MCP.
```

### GitHub MCP Tool Selection
- Use `create_or_update_file` for single-file commits (handles SHA for updates).
- Use `push_files` for atomic multi-file commits or when the simpler tool fails.
- For a new file, no SHA is needed — the tool creates it. For updates, fetch the current SHA first.

### Fallback Gracefully When Data Is Sparse
When Sigil returns empty results, the right response is: report what was found (index lag), generate the digest from available context (current conversation), and still commit — a digest noting "no sessions" is still valuable for audit continuity.

## 3. How Enterprise Customers Use This at Scale

### Automated Knowledge Capture Across Teams
Large enterprises (500+ engineers) use daily digest automations to capture institutional knowledge before it disappears into chat history. Common patterns:
- **Per-team digests:** Each squad runs its own digest automation scoped to its Grafana org or stack, committed to a shared mono-repo under `teams/<team-name>/digests/`.
- **Weekly rollup automation:** A separate automation runs every Monday, reading the seven daily digest files and producing a weekly summary committed to `weekly-summaries/`.
- **Changelog integration:** Digest commits are picked up by GitHub Actions that post summaries to Slack or Confluence automatically.

### Sigil at Enterprise Scale
- Enterprises query Sigil to measure **AI tool adoption** across squads: which teams use Assistant most, which agents are called, token consumption trends.
- Digest workflows are paired with Sigil `conversation_stats` calls to produce **weekly token usage reports** for FinOps teams.
- **Evaluation rules** in Sigil score Assistant responses for accuracy, tagging low-confidence answers for human review.

### GitHub MCP Integration Patterns
- Enterprises gate digest commits behind a **PR workflow** for regulated environments (SOC2, HIPAA) — committed to a `digests/<date>` branch, PR auto-opened for a documentation owner to approve.
- Some teams use `push_files` to commit dashboards-as-code (JSON), skills, and digests atomically in one commit, keeping change history unified.
- **CODEOWNERS** files route digest PRs to a designated knowledge-management owner rather than oncall engineers.

### Runbook and Skills Automation
- Enterprises maintain a `skills/` directory in the same repo, and digest automations also commit newly discovered prompt patterns as skills, making them available to all team members via the Grafana Assistant skills knowledgebase.
- Skills are scoped to `tenant` level so every engineer inherits learned patterns without having to discover them independently.

## 4. Real-World Business Impact

### Reduced Knowledge Loss During Oncall Rotations
Daily digests create a written handoff record for oncall engineers. When a rotation changes, the incoming engineer reads the last 3–5 daily digests to understand what was investigated, configured, and learned — cutting ramp-up time from 30–60 minutes of Slack archaeology to under 5 minutes.
> **Customer framing:** "Every shift change costs 45 minutes of context reconstruction. Automated digests eliminate that entirely."

### Faster Post-Incident Documentation
Digest files serve as raw material for post-incident reviews (PIRs). Instead of reconstructing a timeline from memory, the SRE exports the digest from the incident date and pastes it into the PIR template. This compresses PIR authoring from 2 hours to 20 minutes.
> **Customer framing:** "Compliance teams require incident documentation within 24 hours. Automated digests make that a zero-effort byproduct of normal work."

### Measurable MTTR Reduction via Prompt Reuse
Capturing effective prompt patterns and committing them as skills means the next engineer facing the same problem reaches a solution 40–60% faster. Over a quarter, teams report meaningful MTTR reductions on recurring incident types.
> **Customer framing:** "Every prompt pattern you capture is a template your whole team uses automatically — compounding returns on every investigation."

### Audit Trail for AI-Assisted Operations
In regulated industries (healthcare, finance), enterprises need to demonstrate that AI-assisted decisions were reviewed by a human. Digest commits with timestamps provide an immutable audit trail: what the assistant recommended, when, and (via PR approval) who reviewed it.
> **Customer framing:** "This is your evidence of human oversight for SOC2 and HIPAA auditors — generated automatically."

### Cost Visibility via Token Tracking
Digests that include Sigil `conversation_stats` (token usage) give FinOps teams per-team AI cost attribution, feeding directly into CMAB usage-alert workflows before overage occurs.
> **Customer framing:** "You get the productivity gains of AI-assisted operations AND the cost controls your finance team demands."
