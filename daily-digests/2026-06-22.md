## 2. Key Learnings

- **Sigil is the source of truth for conversation history.** The `list_conversations` operation returns sessions in reverse-chronological order with `created_at` timestamps. Filter by comparing against the UTC window — do not rely on conversation titles (they default to the conversation UUID when untitled).
- **Digest automation requires a no-data path.** When no conversations exist in the window, the digest should still commit — recording the absence of activity is itself useful signal (especially for compliance and audit trails).
- **GitHub MCP `push_files` is preferred over `create_or_update_file` for new files** when you do not need to provide a blob SHA, and when you want to commit in a single API call.
- **The digest prompt pattern that works:** `Review my last 24 hours of conversations → structured Markdown sections → commit to repo`. This is a reusable automation prompt — consider scheduling it via Grafana Assistant Automations (`/a/grafana-assistant-app/settings/automations`) on a daily cron (e.g., `0 6 * * *` for 6 AM local time) so it runs without manual invocation.
- **Conversation titles are not reliable for search.** Sessions without a user-set title use the conversation UUID as the title. Use `get_conversation` with the ID to retrieve the actual prompt/generation content if richer analysis is needed.

## 3. How Enterprise Customers Use This at Scale

### Daily Digest Automation
Large platform engineering teams schedule this pattern as a tenant-scoped Grafana Automation running on a daily cron. The digest is committed to a shared Git repo (often the same repo as their IaC/dashboard-as-code), creating a durable, version-controlled record of every Assistant interaction. Teams use this for:
- **Onboarding acceleration:** New engineers review digest history to understand what queries, dashboards, and investigations their teammates have run — reducing ramp-up time.
- **Knowledge management:** Recurring queries are extracted from digests and promoted into Skills, so the Assistant learns from team patterns over time.
- **Audit and compliance:** Regulated industries (healthcare, finance) require records of AI-assisted decisions. Daily digests committed to Git provide an immutable, reviewable trail.

### GitHub MCP at Scale
Enterprise teams connect the GitHub MCP to Grafana Assistant to enable GitOps workflows for observability artifacts:
- Dashboard JSON is committed on creation/modification, with PR-based review before production promotion.
- Alert rule changes are diffed against the previous commit and summarized in Slack via IRM webhooks.
- Runbooks and Skills are co-located with dashboard code so context stays synchronized.

### Sigil (AI Observability) at Scale
Platform teams use Sigil to monitor the Assistant itself as an AI workload:
- Track conversation volume, model usage, error rates, and latency across all users in the tenant.
- Set evaluation rules to flag low-quality or off-topic responses.
- Use `conversation_stats` aggregations to identify which teams are getting the most value and which workflows need better Skills or rules.
- Feed Sigil data into Grafana dashboards for executive-level AI adoption reporting.
