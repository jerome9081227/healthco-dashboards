## 2. Key Learnings

### Automation-Context Security Boundary Is Real and By Design
`manage_automations` is blocked when running inside an automation-triggered task. Automations cannot self-list, self-modify, or chain into other automations at runtime. This is not a bug — it is a deliberate isolation boundary. Design automation workflows assuming they cannot introspect themselves. If you need to pass state between automation runs, use the GitHub commit log or a skill body as the persistence layer.

### Sigil Conversation Indexing Has a ~24h Latency Window
Sigil's `list_conversations` and `search_conversations` return no data for today's sessions. The indexing pipeline is not real-time. **Fallback pattern:** treat the current conversation as the primary evidence source; use GitHub commit history for session continuity across days. This digest chain (18+ days, zero gaps) is more reliable than the Sigil conversation index for historical continuity.

### Two-Run Digest Pattern Creates Morning vs. Night Snapshots
Running the digest at both 11 PM and 11:50 PM today demonstrates that the automation produces stable, idempotent output — the second run overwrites the first with a richer final version. This two-pass pattern (preliminary snapshot + final replacement) is useful when multiple events happen late in the day after the first run.

### Skills + Automations = Composable Workflow Engine in Plain English
The HealthCo digest pipeline has no code: a Skill (prompt runbook) + an Automation (scheduler) + GitHub MCP (output sink) produce a production-grade daily artifact. The Skill body IS the spec. Changing one sentence in the skill changes the output of every future run. This is observability-as-code applied to AI workflows.

### Digest as the Continuity Layer Between Sessions
When conversation history is unavailable (Sigil indexing gap, session expiry, automation isolation), the git commit log IS the audit trail. 18+ days of `daily-digests/YYYY-MM-DD.md` files give a timestamped record of every configuration decision, alert state, and learning. This is more durable than any in-memory session context.

### 3-Arrow Coverage Scales as a Sales Asset
When every learning, pattern, and impact story in the digest generates a 3-arrow entry, a single day produces 8–15 entries. Over 30 days, that accumulates to 250–450 sales-ready entries covering the full observability surface — alert configuration, GitHub integration, AI-assisted diagnosis, SLO management, and more.
