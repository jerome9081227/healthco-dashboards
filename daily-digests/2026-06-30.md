## 3. How Enterprise Customers Use This at Scale

### SLO Architecture at Scale
Enterprise healthcare customers configure SLOs per clinical API surface rather than per infrastructure component. Each SLO generates multi-window burn-rate recording rules automatically via Grafana's SLO API. At scale — 50+ services — this means 500+ recording rules are managed declaratively. CI/CD pipelines validate SLO definitions (target, time window, datasource) before applying to production. A central SRE team sets burn-rate thresholds and notification policies; application teams own the SLO definitions themselves.

### Golden Signal Template Stamping
The inventory-service and order-processor golden signal groups (latency-p99, traffic-absent, error-rate, saturation) represent the textbook RED/USE method applied per microservice. Enterprises codify this as a Terraform module or Jsonnet library — when a new service is deployed, its golden signal alert group is created automatically. Health=error detection is built into the template: a meta-alert fires when any rule evaluation fails, surfacing evaluation outages before they become blind spots.

### Multi-Team Alert Routing for Regulated Industries
In healthcare environments, alert routing is tiered by clinical impact. Clinical API alerts (cardiology, oncology) page the on-call clinical engineering team with a 2-minute response SLA and route to a dedicated PagerDuty service. Infrastructure alerts (GCP, inventory-service, order-processor) page the platform SRE team with a 5-minute SLA. Grafana's notification policy tree with label matchers (`team=clinical`, `team=platform`) implements this without duplicating alert rules. Mute timings block non-critical alerts during scheduled maintenance windows.

### Frontend Observability at Scale
Faro/RUM + Core Web Vitals alerting is deployed to all patient-facing and clinician-facing surfaces. Enterprises correlate deployment events (from CI/CD) with LCP regressions using Grafana annotations. Real-user sessions from clinical workflows are anonymized and sampled before forwarding to Grafana Cloud, satisfying HIPAA data minimization requirements. Error-count alerts are tuned per-surface: clinical UIs have tighter thresholds than marketing pages.

### Automation + GitHub as a Compliance Artifact
Nightly digest automations committed to Git create an informal compliance artifact: timestamped evidence of what was monitored, what was firing, and what actions were taken. During SOC 2 and HIPAA audits, reviewers can query the git history to confirm continuous monitoring was active on any given date. This costs nothing beyond the automation already running.

### Alert Evaluation Health Monitoring
Enterprise SRE teams add a meta-monitoring layer: Prometheus queries that count `grafana_alerting_rule_evaluations_total{state="error"}` and alert when nonzero. This ensures that evaluation failures — which silently suppress notifications — are caught within minutes. The meta-alert routes to a dedicated channel separate from application alerts to avoid confusion.
