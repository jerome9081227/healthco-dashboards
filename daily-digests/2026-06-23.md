## 2. Key Learnings

### Sigil Coverage Gap
- Sigil indexes conversations asynchronously; the **current in-flight session is not yet available** via `list_conversations` or `search_conversations`. Always account for a lag of minutes to hours when querying your own session.
- Sessions older than the 24-hour window will not appear in filtered searches. If no results return, validate the time bounds before concluding "nothing happened today."

### Deferred Tool Discovery
- MCP tools (like GitHub) are not in the default tool manifest — they must be discovered at runtime via `tool_search_tool_bm25`. The pattern `github commit file repository` reliably surfaces `push_files` and `create_or_update_file`.
- Using `push_files` is preferred over `create_or_update_file` for new files because it does not require a pre-existing SHA.

## 3. How Enterprise Customers Use This at Scale

### Daily Digest at Enterprise Scale
Large organizations (50–500+ Grafana users) use automated daily digests to:
- **Audit AI assistant usage** across teams — what queries were run, which datasources accessed, which alerts investigated
- **Generate per-team summaries** by filtering Sigil conversations by `agent`, `namespace`, or `cluster` label to scope digests to a specific squad
- **Feed into ITSM systems** — digest Markdown committed to GitHub can trigger downstream GitHub Actions that open Confluence pages, Jira tickets, or Slack summaries

### GitHub as Observability Knowledge Base
- Enterprise teams version-control dashboards, alert rules, and investigation runbooks in GitHub alongside these digests
- Pull request workflows enforce peer review on dashboard changes before they reach production
- Tags like `environment: prod` on commits tie Grafana changes to deployment events, enabling timeline correlation during incidents

### MCP Server Fleet Management
- Enterprises configure MCP servers at **tenant scope** (not user scope) so all team members share the same GitHub, Jira, or Notion integration without individual setup
- Admin-managed MCP registrations are auditable and can be locked to specific repos/orgs for compliance
- Role-based access: `Assistant MCP User` role gates who can add personal MCP servers; `Assistant Admin` manages tenant-wide ones

### Sigil for LLM Governance
- Enterprises run `conversation_stats` queries on a schedule to track: volume by agent/model, error rates, average generation latency, and evaluation pass rates
- This data feeds SLA reporting — e.g., "AI assistant responded within 5s for 99.2% of queries this week"
- Guards and evaluation rules (via Sigil Evals) are configured to automatically flag off-topic or policy-violating conversations at scale
