## 3. How Enterprise Customers Use This at Scale

### Conversation Observability with Sigil
Large enterprises instrument every AI assistant interaction through Sigil to build audit trails, enforce evaluation policies, and measure model quality at scale:

- **Centralized evaluation pipelines:** Every conversation is scored by automated evaluators (hallucination detection, policy compliance, response quality). Scores feed into dashboards monitored by AI governance teams.
- **Multi-team attribution:** Conversations are tagged by team, environment, and agent version. Per-team usage reports inform budget allocation and LLM cost chargeback.
- **Automated guardrails:** Guards block or flag conversations that match policy violations (PII leakage, off-topic queries, unsafe outputs) before responses reach end users — enforced at the platform level, invisible to end users.
- **Evaluation collections:** Platform teams build curated test sets ("evaluation collections") and run them on every model upgrade to catch regressions before promoting to production.

### Daily Digest Automations
Enterprises schedule digest automations on a cron (`0 6 * * 1-5`) to generate and push operational reports to shared GitHub repositories, Confluence, or Slack channels:

- **Shift handoffs:** Night-shift SREs produce a structured summary committed to a shared repo before the day-shift standup — replacing ad hoc Slack threads with a durable, searchable record.
- **Compliance snapshots:** SOC 2 / ISO 27001 environments require immutable, timestamped records of all observability actions. Git commits provide that audit trail automatically with zero additional tooling.
- **Executive reporting:** Weekly digests are rolled up from daily Markdown files and surfaced in stakeholder dashboards or emailed via Grafana alerting contact points.

### GitHub MCP at Scale
Enterprise platform teams configure the GitHub MCP at the **tenant level** so all engineers can commit observability artifacts (dashboards-as-code, runbooks, SLO definitions) directly from assistant sessions:

- **GitOps for dashboards:** Engineers describe a dashboard in natural language → assistant generates the panel JSON → commits to a feature branch → PR opened for peer review. Grafana dashboard-as-code + Git history replaces fragile manual exports.
- **Runbook automation:** Alert enrichments trigger assistant investigations; findings are committed as `post-mortems/YYYY-MM-DD.md` automatically, building a searchable institutional memory.
- **Skill versioning:** Custom assistant skills are stored in GitHub and synced back into Grafana, enabling peer review, approval workflows, and rollback — the same lifecycle as application code.
- **Volume:** Teams operating at scale commit dozens of observability artifacts per day this way, reducing "undocumented dashboard" sprawl and keeping configuration in sync with infrastructure changes.
