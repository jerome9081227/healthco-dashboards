## 2. Key Learnings

### Agent Observability Does Not Index Live Sessions in Real Time
The `agento11y_query` `search_conversations` tool returned zero results for a search covering the full July 18 ET day in UTC. Today's current session is not available for review while it is still active. This is an important operational limitation:
- **Implication:** The automated 11:50 PM digest fires before today's late-evening sessions are indexed.
- **Workaround:** GitHub commit history is the most reliable same-day activity log. It is authoritative, append-only, and never delayed.
- **Better pattern:** Structure important work to leave Git artifacts (commits, PRs, file updates) as the primary audit trail — not just conversation history.

### The Multi-Source Correlation Pattern for Digest Generation
When Agent Observability has no data, a complete digest can still be generated by triangulating three sources:
1. **GitHub commit history** — what was built, when, by whom, with what message
2. **Skills** — the documented environment state and procedural context
3. **Current conversation context** — what tools were called, what was discovered

This is the same pattern used in production incident post-mortems: correlate signals from multiple sources when no single source is complete.

### Manual Digest Runs Are "Preview" Runs of the Automated Pipeline
Running the Daily Learnings skill at 10 PM ET (vs. the scheduled 11:50 PM) produces a preview digest with slightly less end-of-day coverage. This is useful for:
- Validating the automation pipeline is working before the scheduled run
- Generating a draft that can be reviewed and refined before the authoritative commit
- Catching indexing or tool failures while there's still time to correct them

### The Daily Digest Directory Has 23 Files — A 7-Week Knowledge Archive
The `daily-digests/` directory now contains 23 files spanning from 2026-06-05 through today. This is a living, queryable knowledge base:

### `health=error` on Alert Rules Is a Rule Configuration Signal, Not a Service Signal
Confirmed again from the 2026-07-17 digest: when a newly deployed alert rule group shows `health=error` across all rules simultaneously, the root cause is almost always a datasource UID mismatch or query syntax error — not an actual service incident. This diagnostic shortcut saves 5–10 minutes per incident triage cycle.

## 3. How Enterprise Customers Use This at Scale

### GitHub as the Authoritative Observability Audit Trail
Enterprise teams that have adopted GitOps for monitoring-as-code treat the Git commit history as their primary change log. This means:
- Every alert rule change, threshold adjustment, dashboard modification, and SLO target update has a commit SHA, author, timestamp, and message
- Compliance auditors receive a GitHub link instead of a spreadsheet
- Post-incident reviews start with `git log --since="2 hours ago"` to find what changed before the incident
- At scale (500+ engineers), teams run automated "change correlation" jobs that cross-reference Git commits against alert firing events to detect regression-introducing deployments within seconds

### Daily Digest Automation as Enterprise Knowledge Management
Large enterprises lose institutional knowledge at team transitions, reorgs, and on-call handovers. The daily digest automation pattern directly solves this:
- Each digest is a structured, searchable artifact committed to the company's central observability repo
- New team members onboard by reading the last 30 digests — 7 weeks of operational context in structured Markdown
- The weekly rollup automation (a logical next step) generates a "this week in observability" email to engineering leadership
- Enterprise teams extend this with a "digest-to-Confluence" or "digest-to-Notion" integration via the same MCP pattern

### Multi-Source Correlation as a Core Incident Response Skill
The pattern demonstrated today — correlate GitHub + observability tools + skills when no single source is complete — is the same pattern enterprise SRE teams apply during major incidents:
- PagerDuty alerts fire → IRM incident opened → on-call queries metrics, logs, traces
- If telemetry is degraded, pivot to: recent deploys (GitHub), CMDB changes (ServiceNow), cloud provider status pages
- The mental model is "never block on a single source; always triangulate"
- Grafana Assistant's multi-tool architecture natively supports this pattern in a single chat interface

### SLO Documentation Drift Prevention at Scale
Enterprises with 100+ SLOs face a constant documentation drift problem: SLOs are created, targets change, services are renamed, and no one updates the runbooks. The pattern that prevents this at scale:
- Every SLO creation PR includes a documentation update as a required check
- A weekly automation diffs the live Grafana SLO API against the canonical skills/runbook content and opens a GitHub issue when drift is detected
- The HealthCo case (3 documented vs. 12 live SLOs) is a textbook example of why this automation is needed
- Grafana's `grafana_slo_*` metric family can be used to count live SLOs and compare against the skills library count programmatically

### Agent Observability Indexing Lag as an Enterprise Design Constraint
Enterprise teams building automation pipelines on top of Agent Observability need to account for indexing latency:
- Don't schedule automated digests to run immediately at end-of-session; build in a 30–60 minute buffer
- Use Git as the primary activity log; use Agent Observability as the supplementary semantic/context log
- For compliance pipelines where conversation records are evidence, the 11:50 PM schedule is appropriate (sessions from ~10 PM onward may still be partially indexed)
- Consider a "fallback to Git" logic path in automation prompts: "if Agent Observability returns zero results for today, use GitHub commit history as the primary source"

## 4. Real-World Business Impact

### Zero-Gap Digest Generation Builds Trust in the Automation Pipeline
The ability to generate a complete, accurate digest even when Agent Observability returns zero results proves the pipeline is resilient. For a healthcare organization, automation reliability is not optional — clinical teams need to trust that their morning briefing is complete, not "we got nothing from the observability API last night." Demonstrating graceful fallback behavior builds stakeholder confidence.

**Customer-facing framing:** "Our daily observability digest generates even when the primary data source is unavailable. We built in fallback logic — just like we do for patient-facing services. The morning briefing never goes dark."

### A 7-Week Knowledge Archive Reduces Onboarding Time by Weeks
The 23-file digest archive in `healthco-dashboards/daily-digests/` represents 7 weeks of structured operational context. A new SRE joining the HealthCo platform team can read 7 weeks of digests in 2–3 hours and understand the full evolution of the monitoring environment: what alerts were created, what SLOs cover which services, what incidents occurred, what the team learned. Traditional onboarding via shadowing and tribal knowledge takes 2–4 weeks.

**Customer-facing framing:** "We have 7 weeks of structured operational history committed to Git. When we onboard a new engineer, the full context of every monitoring decision we've made is available in structured Markdown. We've turned institutional knowledge into code."

### SLO Count Drift Detection Protects Clinical Compliance
Discovering that the live environment has 12 SLOs while documentation says 3 is a compliance risk for a healthcare organization. If an auditor asks "which clinical APIs have formal availability commitments?" and the answer doesn't match reality, that's a finding. Detecting and closing this gap before an audit is direct compliance risk reduction.

**Customer-facing framing:** "We found a documentation gap — 12 live SLOs, only 3 documented. In a HIPAA audit, that's a control failure. We caught it in a 10-minute digest review, not during an audit. That's the value of automated documentation validation."

### The Multi-Source Correlation Pattern Reduces Triage Time During Degraded Observability
During the incidents where telemetry itself is impaired (Loki down, Prometheus scrape failing), teams that know how to pivot to Git, status pages, and structured skill documentation resolve incidents faster. The "never block on a single source" pattern, practiced daily in the digest workflow, becomes muscle memory for on-call engineers.

**Customer-facing framing:** "We practice our fallback investigation patterns every day through the digest workflow. When observability itself fails during an incident, our team already knows exactly how to pivot to Git history and documentation. The training is built into the daily routine."

### Automating Documentation Reduces Compliance Labor Cost
Manual compliance documentation (change logs, alert rule inventories, SLO registers) typically consumes 1–2 hours per engineer per sprint. With the digest automation + GitHub commit history as the system of record, this labor is eliminated. For a 10-person platform team, that's 20–40 hours per sprint returned to engineering work.

**Customer-facing framing:** "We automated our compliance documentation. The monitoring team gets 20–40 hours per sprint back from manual change logging. That's equivalent to hiring an extra engineer for compliance work."
