## 3. How Enterprise Customers Use This at Scale

### Daily Digest Automation at Scale
Large teams run this pattern as a **scheduled Grafana Assistant Automation** (cron: `0 7 * * 1-5`) that fires every weekday morning. The digest is committed to a shared Git repo (often a monorepo or a dedicated `ops-runbooks` repo), creating a searchable, auditable log of every configuration change made via Assistant. Teams in regulated industries (healthcare, finance) use this as lightweight evidence for change-control processes.

### AI Observability (Sigil) at Scale
Enterprise customers connect every LLM-powered internal tool to Sigil to get a unified view of AI traffic: which models are used, error rates, latency distributions, and cost per conversation. Platform teams use `search_conversations` with `agent=` filters to audit specific assistants (e.g., a coding copilot, a support bot) independently. Evaluation rules are layered on top to flag hallucinations or policy violations automatically.

### GitHub MCP at Scale
Platform engineering teams configure the GitHub MCP server once at the tenant scope, making it available to all Assistant users. They scope OAuth tokens to specific repos (e.g., `healthco-dashboards`) to enforce least-privilege. Common workflows driven through the MCP: creating runbook PRs from incident summaries, committing alert rule changes for review, and archiving investigation findings as markdown in a knowledge repo.

### Structured Knowledge Repositories
Enterprise customers maintain a Git-backed knowledge repo (like `healthco-dashboards`) that stores:
- `daily-digests/` — session recaps (this pattern)
- `runbooks/` — investigation playbooks generated by Assistant
- `dashboards/` — exported or version-controlled Grafana dashboard JSON
- `alerts/` — Terraform or Jsonnet alert rule definitions

This gives platform teams a single source of truth that is both human-readable and CI/CD-compatible.
